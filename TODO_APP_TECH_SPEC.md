# Техническое задание: Todo-приложение

## 1. Описание проекта

Todo-приложение — это веб-приложение для создания, просмотра, редактирования и удаления задач.

Проект создаётся в учебных целях, чтобы попрактиковаться в разработке backend на **FastAPI** и frontend на **React**.

Приложение должно позволять пользователю управлять списком задач через удобный интерфейс в браузере.

---

## 2. Цели проекта

Основные цели:

- Научиться создавать REST API на FastAPI.
- Научиться подключать frontend на React к backend API.
- Понять основы CRUD-операций.
- Научиться работать с базой данных.
- Разобраться с валидацией данных.
- Получить первый полноценный проект для портфолио.

## 4. Основной функционал

### 4.1. Список задач

Пользователь должен видеть список всех задач.

Каждая задача должна содержать:

- ID
- Название
- Описание
- Статус выполнения
- Дату создания

Пример задачи:

```json
{
  "id": 1,
  "title": "Выучить FastAPI",
  "description": "Пройти основы и сделать CRUD",
  "is_completed": false,
  "created_at": "2026-10-13T14:30:00"
}
```

---

### 4.2. Создание задачи

Пользователь должен иметь возможность создать новую задачу.

Поля при создании:

- Название задачи — обязательное поле
- Описание задачи — необязательное поле

Требования:

- Название не должно быть пустым.
- После создания задача появляется в общем списке.
- По умолчанию новая задача имеет статус `is_completed = false`.

---

### 4.3. Редактирование задачи

Пользователь должен иметь возможность изменить:

- Название задачи
- Описание задачи
- Статус выполнения

Например, пользователь может отметить задачу как выполненную.

---

### 4.4. Удаление задачи

Пользователь должен иметь возможность удалить задачу.

После удаления задача больше не отображается в списке.

---

### 4.5. Просмотр одной задачи

Пользователь должен иметь возможность открыть одну конкретную задачу по её ID.

## 6. API endpoints

### 6.1. Получить все задачи

```http
GET /todos
```

Описание:

Возвращает список всех задач.

Пример ответа:

```json
[
  {
    "id": 1,
    "title": "Выучить FastAPI",
    "description": "Сделать Todo API",
    "is_completed": false,
    "created_at": "2026-10-13T14:30:00"
  }
]
```

---

### 6.2. Получить одну задачу

```http
GET /todos/{todo_id}
```

Описание:

Возвращает одну задачу по ID.

Пример ответа:

```json
{
  "id": 1,
  "title": "Выучить FastAPI",
  "description": "Сделать Todo API",
  "is_completed": false,
  "created_at": "2026-10-13T14:30:00"
}
```

Если задача не найдена, вернуть ошибку:

```json
{
  "detail": "Todo not found"
}
```

HTTP-статус:

```http
404 Not Found
```

---

### 6.3. Создать задачу

```http
POST /todos
```

Тело запроса:

```json
{
  "title": "Новая задача",
  "description": "Описание задачи"
}
```

Пример ответа:

```json
{
  "id": 2,
  "title": "Новая задача",
  "description": "Описание задачи",
  "is_completed": false,
  "created_at": "2026-10-13T14:35:00"
}
```

HTTP-статус:

```http
201 Created
```

---

### 6.4. Обновить задачу

```http
PUT /todos/{todo_id}
```

Тело запроса:

```json
{
  "title": "Обновлённая задача",
  "description": "Новое описание",
  "is_completed": true
}
```

Пример ответа:

```json
{
  "id": 1,
  "title": "Обновлённая задача",
  "description": "Новое описание",
  "is_completed": true,
  "created_at": "2026-10-13T14:30:00"
}
```

---

### 6.5. Удалить задачу

```http
DELETE /todos/{todo_id}
```

Пример ответа:

```json
{
  "message": "Todo deleted successfully"
}
```

Если задача не найдена, вернуть:

```json
{
  "detail": "Todo not found"
}
```

## 7. Структура базы данных

Для первой версии проекта можно использовать SQLite.

Название базы данных:

```text

```

Таблица:

```text
todos
```

Поля таблицы:

| Поле | Тип | Описание |
|---|---|---|
| id | integer | Уникальный ID задачи |
| title | string | Название задачи |
| description | string | Описание задачи |
| is_completed | boolean | Выполнена задача или нет |
| created_at | datetime | Дата создания задачи |

## 11. Состояния задач

У задачи должно быть два состояния:

```text
Не выполнена
Выполнена
```

Если задача выполнена, её можно визуально выделить:

- зачеркнуть текст;
- сделать текст серым;
- показать галочку.

---

## 12. Валидация

### Backend

Backend должен проверять:

- `title` не должен быть пустым;
- `title` должен быть строкой;
- `description` может быть пустым;
- `is_completed` должен быть boolean.

### Frontend

Frontend должен проверять:

- пользователь не может создать задачу без названия;
- при ошибке нужно показать сообщение пользователю.

Пример ошибки:

```text
Введите название задачи
```

---

## 13. Обработка ошибок

Приложение должно корректно обрабатывать ошибки.

Примеры ошибок:

| Ситуация | Что показать |
|---|---|
| Backend недоступен | Не удалось загрузить задачи |
| Задача не найдена | Задача не найдена |
| Пустое название | Введите название задачи |
| Ошибка при удалении | Не удалось удалить задачу |
| Ошибка при сохранении | Не удалось сохранить задачу |

---

## 14. CORS

Так как frontend и backend будут запускаться на разных портах, нужно настроить CORS.

Пример:

```text
Frontend: http://localhost:5173
Backend: http://localhost:8000
```

Backend должен разрешать запросы с frontend-адреса.

## 15. Команды запуска

### Backend

Перейти в папку backend:

```bash
cd backend
```

Создать виртуальное окружение:

```bash
python -m venv venv
```

Активировать виртуальное окружение:

Для Windows:

```bash
venv\Scripts\activate
```

Для macOS/Linux:

```bash
source venv/bin/activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Запустить сервер:

```bash
uvicorn app.main:app --reload
```

Backend будет доступен по адресу:

```text
http://localhost:8000
```

Swagger-документация:

```text
http://localhost:8000/docs
```

---

### Frontend

Перейти в папку frontend:

```bash
cd frontend
```

Установить зависимости:

```bash
npm install
```

Запустить frontend:

```bash
npm run dev
```

Frontend будет доступен по адресу:

```text
http://localhost:5173
```

## 22. Рекомендация для начинающего

Не пытайся сразу сделать всё идеально.

Лучше идти по шагам:

1. Сначала сделай backend без frontend.
2. Проверь API через Swagger UI.
3. Потом сделай простой frontend.
4. Подключи frontend к backend.
5. Только потом улучшай внешний вид и добавляй новые функции.

Главная цель проекта — понять, как frontend и backend общаются между собой.
